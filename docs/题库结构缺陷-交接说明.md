# 题库结构缺陷 · 交接说明

写给接手的模型。这份文档只讲**卡在哪、为什么卡、我判断该往哪走**，不讲具体步骤——路怎么走由你定。

日期：2026-08-25 · 对应提交：`f46beff`

---

## 一句话

题库 5600 题里 **95.2% 是健康的**，剩下的问题**几乎全部集中在一件事上**：有 349 个题组的「选项结构」是导入器编出来的，不是书上印的。四轮人工/模型校对已经把这件事**诊断得非常彻底**，但流水线的设计决定了它们只能诊断、不能修。

现在需要的不是再抄一遍页面，是把已有的诊断变成结构修正。

## 一、卡在哪

跑一次门就能看到当前状态：

```
python scripts/verify_cambridge.py --baseline --health
→ ok: true, damagedQuestions: 267, contentGaps: 673, healthPct: 95.2
```

`contentGaps` 673 里的绝大多数，来自 **443 个被标记为 `flagged` 的题组**。这些组的校对者都看过原书扫描页，都写下了理由，理由高度一致，形态如下：

| 数量 | 页面上真实是什么 | 题库声明的是什么 |
|---:|---|---|
| 113 | 每题自带 4–5 个独立选项的单选题（A–D / A–E） | 组级共享 A–H，全空 |
| 112 | 段落匹配 / List of Headings（A–F、A–G、i–viii） | 组级共享 A–H，全空 |
| 55 | 选词填空，词库 A–P（16 个词） | 组级共享 A–H，全空 |
| 36 | TRUE / FALSE / NOT GIVEN 判断题 | 组级共享 A–H，全空 |
| 24 | 地图 / 图表标注，字母印在图上（A–J） | 组级共享 A–H，全空 |
| 20 | 三选一 / 三分类（A–C） | 组级共享 A–H，全空 |
| 16 | **PDF 扫描件本身缺页**（例：C13 T3 印刷页 54–55 没被扫进去） | — |
| 67 | 其它（多为 A–E、A–I 等其它宽度） | 组级共享 A–H，全空 |

真实样本（`fixtures/overlays/` 里的 `note` 字段原文）：

> `cambridge-4-test-1-reading/c4t1r-g40`
> "Printed page 27 has single-choice question 40 with 4 options (A-D), but fixture declares 8 empty options"

> `cambridge-6-test-3-listening/c6t3l-g14`
> "页面实际为 Questions 14-17 地图标记题（ROSEWOOD HOUSE AND GARDENS），地图上标记为 A-J 共10个位置字母，无独立文本选项"

除了那 16 条扫描缺页，**这些判断都是对的**。我逐条抽验过其中几条，对着页面图确认过。**页面没错，题库错了。**

## 二、根因

### 2.1 导入器给每个题组盖了同一个默认形态

从 PDF 重建题库时，凡是看起来像选择题的组，都被写成：

```json
{
  "questionType": "single_choice",
  "sharedOptions": [
    {"id": "A", "label": "A", "text": ""},
    ... 一直到 H，全部 text 为空 ...
  ]
}
```

剑桥根本不这么印。听力三选一印 A–C；List of Headings 印罗马数字 i–viii；段落定位题用文章自己的段落字母 A–F；词库填空可以宽到 A–P；判断题压根没有字母选项；地图题的字母印在图上而不是列表里。

一个默认形态套了九种真实题型，**其中八种是错的**。

当前全库还剩 **349 组**保持着这个 `A–H 全空` 的原始形态（`fixtures/cambridge/*.json`，共 5599 组）。

### 2.2 流水线能修内容，不能修结构

校对流水线（`scripts/repair/`）的设计前提是：**结构是对的，缺的是文字**。所以提交校验器 `72_write_group_overlay.py` 要求提交的 `options` 必须覆盖工单声明的每一个标签。

于是校对者面对一个「声明 A–H、页面只有 A–D」的组时，处境是：

- 照实填 A–D → 校验器拒收（没覆盖 E–H）
- 编造 E–H → 违反「不许猜」的第一纪律，也污染题库
- **只能 flag**

443 条 flag 不是偷懒，是**唯一合规的出路**。这是流水线的结构性限制，不是执行者的问题。

### 2.3 为什么我的自动修复只能走到这里

我写了两个脚本处理这件事（都已合入）：

- `scripts/repair/64_fix_option_structure.py` —— 按组的印刷说明（rubric）把选项集裁到真实宽度，裁正 374 处；并把被解析器扫进题干的选项文字抬回选项位，恢复 42 处。
- `scripts/repair/65_mechanical_repairs.py` —— 清掉 36 组「填空题却挂着空选项槽」的幽灵选项，以及若干竖线/题型/粘字的机械修复。

它们只能吃掉 rubric 本身讲清楚了结构的那部分。剩下的 349 组，**rubric 要么是占位符，要么本身就是错的**——这才是真正的墙，见下一节。

## 三、发生过什么

四轮，缺口从 1638 压到 673（-59%）：

| 轮次 | 做了什么 | 缺口 |
|---|---|---|
| 1 | 题干 + 答案键，2790 处 | — |
| 2–3 | 组级校对：补题目说明与选项文字 | 1638 → 1005 |
| — | 我修选项结构 + 两篇丢失的阅读文章 | 1005 → 709 |
| 4 | 重开第三轮被 flag 的组（结构修好后堵点消失）| 709 → 673 |

第四轮的意义值得单独说：修完结构后重开，**670 组里有 227 组当场解决了**（144 corrected + 83 approved）。这证明「先修结构、再抄写」这个顺序是对的。剩下 443 组则暴露出：同一个病还有八种形态，我只修掉了 rubric 讲清楚了的那一种。

**继续派便宜模型抄页面已经没有意义了。** 它们会再交回一批同样正确、同样解决不了问题的 flag —— 第四轮已经演示过一次。

## 四、我的思路

### 4.1 最重要的一点：诊断已经做完了，就在题库里

那 443 条 `note` 是四轮校对留下的**最有价值的资产**。每一条都是一个人/模型对着原书扫描页写下的结论，带印刷页码、带真实选项数、带题型判断。

换句话说：**「这一组到底该长什么样」这个问题，绝大多数已经有答案了，只是答案以散文形式躺在 `fixtures/overlays/*.json` 的 `note` 字段里，没人把它变成结构。**

我会从这里入手。

### 4.2 但不要盲信 note——它和 rubric 一样可能是错的

我踩过这个坑，写下来省得你再踩一次。

我一度以为「rubric 是印刷原文，可以当真理」。抽样打脸：

```
cambridge-10-test-2-listening / c10t2l-g25
  rubric:  "Choose the correct letter, A, B or C."
  选项:    A–E，五个，每个都有真实文字
  答案键:  G
```

这里错的是 **rubric**（一个被误配上去的模板），选项反而是真的。如果按 rubric 裁到 A–C，就会毁掉三个真实选项。

所以：**rubric、note、选项、答案键，四个来源没有一个天然可信。** 需要的是交叉验证，不是选一个来信。

### 4.3 答案键是最独立的证人，但它只给下界

答案键是唯一没被「结构默认值」污染过的信息源。在 349 个 A–H 全空组里，它说的话是这样的：

```
72 组  键最大到 C        68 组  键最大到 B        62 组  键只有 A
48 组  键最大到 D        23 组  键最大到 I        19 组  键最大到 E
18 组  键最大到 F        12 组  键最大到 H        12 组  键最大到 G
12 组  键里含单词  → 一定是填空题，不是选择题
```

**陷阱**：「键最大到 C」不等于「只有三个选项」。它只说明**至少有三个**——一组四选一的题，四道题的答案恰好都落在 A/B/C 是完全正常的。62 组「键只有 A」尤其危险，按字面裁会毁掉一切。

答案键能做的是**证伪**（键出现 I 就绝不可能只有 A–H）和**定性**（键是 TRUE/FALSE/NOT GIVEN 就一定是判断题，键含单词就一定是填空题），不能单独定量。

### 4.4 好消息：目标形态已经存在，而且同一套题库里就有正确样例

Schema 支持的题型是完整的，`src/lib/types.ts`：

```
single_choice | multi_choice | true_false_ng | yes_no_ng | completion | matching | labelling
```

而且题库里**已经在正确使用它们**：552 题 `true_false_ng`、578 题 `matching`、96 题 `labelling`、197 题 `yes_no_ng`。

也就是说，这不是「要设计一个新表示」的问题，是「把 349 个组归到已经存在、已经能正确渲染的类别里」的问题。**每一个坏组，在同一本书里几乎都能找到一个结构正确的同类组作为参照。** 这是我认为最省力的杠杆。

（顺带：有 6 题的 type 是 `short_answer`，而 `QuestionType` 联合类型里没有这个值。Rust 侧返回 `serde_json::Value`，类型漂移是静默的——见 `CLAUDE.md`。这是个独立的小 bug，值得顺手确认。）

### 4.5 关于那 16 条扫描缺页

`C13 T3 Listening` 印刷页 54–55 没被扫进 PDF。这个用任何方法都修不了，除非补扫。我的判断是**接受它**，明确记录成已知缺失，不要让它一直挂在待办里制造噪音。

## 五、硬约束（这几条别碰）

1. **带文字的选项永远不要删。** 我的第一版脚本把 `"Reading Passage 1 has seven paragraphs, A-G"` 里的 A–G 当成选项范围，删光了一组九个真实的罗马数字选项。ratchet 拦住了，`.bak` 救回来了。这是这份文档里最贵的一条经验。

2. **`fixtures/` 是 gitignored 的**，git 救不了你。改动前 `.bak`，或者用 `--dry-run` 先看。唯一的重放手段是 `fixtures/overlays/` + `scripts/repair/40_apply.py`。

3. **ratchet 只能降不能升**（`fixtures/cambridge-health-baseline.json`）。唯一的例外是「检测器变锋利了」——那种情况要重设基线，并在 `note` 里写明为什么。我做过一次：加了「答案键指向本题不提供的选项」这项检查后，damaged 从 232 升到 304，那是门变强了，不是题库变坏了。别把这个例外当成绕过失败的后门。

4. **不许猜。** 页面上没印的字一个都不许写。这条纪律是前四轮质量的全部来源，443 条 flag 正是它在起作用的证据。

5. **`72_write_group_overlay.py` 是唯一的写入口**（经 `40_apply.py` 落地）。如果你决定绕过它直接改 fixtures——那是合理的，因为结构修正本来就不在它的能力范围内——请自己补上等价的校验，别让改动无人把关。

## 七、怎么算做完

我的建议是按这个标准，而不是按「缺口清零」：

- **349 个 A–H 全空组，每一组都归到了正确的题型和真实的选项宽度**——哪怕选项文字还没补，结构对了，抄写轮就能自动化地继续。
- **没有任何一个带文字的选项在过程中消失**（可以对着改动前后自己数一遍，这是唯一的硬回归）。
- **门通过**，`damagedQuestions` 不高于交接时的 267（除非你把门变得更锋利，那就重设基线并写明）。
- 16 条扫描缺页被明确记录为已知缺失，不再计入待办。

缺口不必归零。**673 里有相当一部分是「选项文字缺失」这种抄写活，那个用便宜模型批量做就行——但要等结构修完之后。** 顺序反了就是第四轮那 443 条 flag 的重演。

它们就在 `fixtures/overlays/` 里等着被用起来。祝顺利。
