## 一、为什么要做这一轮

题库里有一批题的答案键是错的——不是「可能错」，是确定错。例：

```
C20 Test 2 Reading Q27–32
  印刷页上：   Do the following statements agree ... YES / NO / NOT GIVEN
  题库里存的： D / G / B / C / B / D
```

考生永远不可能被判对。这类题目前有 263 处，而且第五轮的结构修复卡在这里：题型和答案键互相矛盾时，改题型不改键只会把损坏从一处挪到另一处。

**键的唯一权威是书末印着的答案页。** 那些页大多只以扫描图存在——全库应有 140 个答案区块，文字抽取只拿到 66 个，其中完整的只有 5 个。所以必须有人把它们读出来。

## 二、你要做什么

对每个工单：

1. 读工单 `data-dev/repair/answer-key-tasks/<taskId>.task.json`
2. 打开它 `images` 里列出的答案页渲染图（多数工单只有 1–2 张）
3. 把该区块 **1–40 题的答案全部抄下来**
4. 写成 `data-dev/repair/answer-key-tasks/<taskId>.answer.json`：

```json
{
  "taskId": "cambridge-20-test-2-reading-answerkey",
  "answers": {
    "1": "TRUE",
    "2": "NOT GIVEN",
    "27": "YES",
    "34": ["4.30 pm", "half past four"]
  }
}
```

一题一个值。印刷页上用斜杠给了并列答案（`4.30 (pm) / half past four`）时，写成数组或保留斜杠都行。

5. 先自检，通过后再提交：

```
python scripts/repair/74_write_answer_key.py --task <taskId> --check-only
python scripts/repair/74_write_answer_key.py --task <taskId>
```

（python 用 `G:/python/python.exe`）

## 三、闸门会怎么查你

**这一轮不靠抽检。** 校验器做五件事，每一件都是机器判定：

1. **覆盖**——必须正好是 1–40，一题不少、一题不多。抄串行会在一头丢号、另一头多号，跑不掉。
2. **形状**——每个答案必须是字母 / 罗马数字 / TRUE-FALSE-NOT GIVEN / 短词组之一。把正文句子当答案抄进来会被当场拒收。
3. **区块内形状一致**——剑桥不会在同一个「Questions a–b」里混着判断题和字母题。交替出现超过 4 次就判定为抄串行。
4. **已知答案探针**——工单的 `knownAnswers` 里是文字抽取已经确认过的答案（有的工单多达 37 条）。**你的提交必须和它们每一条都对上**，错一条就整单拒收。这条是替代人工抽检的那道闸。
5. **与题库现有键的一致率**——只报告不拦截（现有键本身就是待查对象），但如果一致率低得离谱，说明有事发生。

拒收是**全单拒收**，不会部分接受——半份答案键比没有更糟，门会拿它去打分。

这五道闸我自测过六种失效模式（全对 / 篡改一条已知答案 / 篡改五条 / 漏题 / 多题 / 拿正文当答案），全部按预期拦截。**自测过程中我还发现并修掉了第 4 条探针的一个 bug**：`knownAnswers` 的键是数字、提交的键是字符串，比较恒不成立，探针曾经形同虚设。现在是好的。

## 四、纪律

- **不许猜。** 页面上没印的、印糊了看不清的，不要编。
- **看不清怎么办**：工单的 `pdfPagesZeroBased` 给了页码，`pdf` 给了原始 PDF 路径，可以自己重渲更高 DPI。仍然不行就**不要提交这一单**，在汇报里说明是哪一单、哪几题、为什么。宁可少一单，不要错一单。
- **不要碰 `fixtures/cambridge/`**。提交只通过 `74_write_answer_key.py`，它写到 `fixtures/answer-keys/`。
- **不要跑 `40_apply.py`、`69_fix_answer_keys.py --apply`、`verify_cambridge.py --update-baseline`**。落地和验收是后续统一做的，并发跑会互相覆盖。
- 只做分给你的工单，不要顺手做别的。
