# 维护与发布指南

面向本仓库维护者。产品说明见根 `README.md`，架构见 `CLAUDE.md`，硬纪律见 `AGENTS.md`。

## 版本

四处必须相同，否则 `package-release.ps1` 和 CI 失败：

| 位置 | 字段 |
|---|---|
| `package.json` | `version` |
| `src-tauri/Cargo.toml` | `[package] version` |
| `src-tauri/tauri.conf.json` | `version` |
| git tag | `v<version>` |

`src-tauri/src/paths.rs` 的 `CONTENT_VERSION` 与 `src-tauri/build.rs` 里的 content-pack 版本应一并改，否则升级不会解出新题库。

## 验证

发布前跑 `.\verify.ps1`，不要只跑 `npm test`。它包含：

1. 有 `fixtures/cambridge/` 时：`verify_cambridge.py --baseline --health` 与内容包校验
2. `scripts/check_styles.py`
3. 根项目与 `site/` 的 `npm audit`（官方 registry，`--audit-level=high`）
4. `cargo audit --file src-tauri/Cargo.lock`
5. vitest、cargo test、`tsc --noEmit`、生产构建

题库损坏 ratchet：`fixtures/cambridge-health-baseline.json` 的数字只能降，不能升。修好后：

```
python scripts/verify_cambridge.py --baseline --update-baseline
```

并把该文件一起提交。不许为了绿灯调高 baseline。

## 题库修复

合并优先级：

```
fixtures/overlays/{exam-id}.json   （人工，最高）
  > data-dev/repair/parsed/…
    > fixtures/cambridge/…         （最低）
```

任何自动解析脚本不得写入或覆盖 `fixtures/overlays/`。缺页见 `docs/known-missing-scans.md`：C13 Test 3 Listening 印刷页 54–55 未扫入前，不得发 v1.3.2，也不得下架或警告绕过。

## 听力音频

只支持剑 4–20、每套恰好四个 Part/Section。不支持整轨，没有时间点校准。导入时后端重算哈希、时长、格式和试卷 ID，不信任前端候选。旧整轨绑定显示「需要重新导入」，不静默删用户文件。

## 发布

```
npm run package:release
```

脚本会跑完整 `verify.ps1`，校验四处版本，签名 NSIS + 便携版，写 `output/release/latest.json`。发布说明取自 `docs/release-notes.md` 对应版本节，或环境变量 `IELTS_RELEASE_NOTES`。

本机安装同步只覆盖 exe，不再镜像整个 `fixtures/` 或 `docs/`。题库由 content-pack 嵌入，安装后解到 `data\content`。

打出新包并确认能启动、进考场、交卷后，立刻删除旧安装包。`output/release/` 不得同时躺两个版本。

GitHub：推 `main`，打 `v<version>` tag。CI 的 `release` job 依赖完整 `verify.ps1`，再跑 `package:release` 并创建 Release。Actions 钉到不可变 commit SHA。
